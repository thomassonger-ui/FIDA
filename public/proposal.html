Why this beats the $5K/month retainer model

Right now, Cole Middleton charges schools roughly $5,000/month for ongoing compliance retainer work plus lump-sum project fees for audit prep and remediation. The retainer runs hot the first three months. By month five, the school stops seeing fresh value — and the relationship churns. That’s $25K–$30K of revenue per school before they walk.

Atticus + à la carte CMG consulting flips that economics. The platform delivers compounding daily value at ~$2,300/month average. CMG keeps earning on top of that — à la carte, not lump-sum — for high-margin audit prep, remediation, accreditation work, and program-launch projects, exactly when the school actually needs them. The platform retains the client; the consulting wins the upside.

Slow and steady — with the platform compounding underneath — beats the lump-sum churn cycle every time. The school stays. Both sides keep earning.

Phase 01 of 4

Tech Foundation

Day 1–7 ~5 hours of active work 10 items

Stand up everything the school needs to run on. Accounts, credentials, repo fork, infrastructure, branding, monitoring — a fully provisioned environment ready for data and integrations to land on top of.

What we’re doing

Each school’s admin team needs shared email and document storage that’s separate from personal accounts. We provision a Google Workspace domain or invite school staff into a shared admin account for compliance documentation.

How we do it
  1. Create or invite to {schoolslug}-admin@workspace
  2. Enable 2FA across all admin accounts
  3. Create shared drive: Atticus — {school name}
  4. Pre-populate with templates: kickoff doc, training schedule, runbook
  5. Add school owner, compliance lead, ops lead as Managers
What we’re doing

Schools don’t typically need GitHub access — Atticus owns the codebase. But if the school has a technical lead who needs visibility, we add them as a read-only collaborator on their own school’s repo (not the master template).

How we do it
  1. Default: school does not get GitHub access
  2. If requested: invite to thomassonger-ui org as outside collaborator
  3. Grant read permission to atticus-{schoolslug} only
  4. Master template atticus-template remains Atticus-only
What we’re doing

The master template at thomassonger-ui/atticus-template contains every workflow, schema, and integration we’ve built. Each new school gets its own fork — same codebase, different brand and configuration.

How we do it
  1. Source: github.com/thomassonger-ui/atticus-template
  2. Use template → create new repo atticus-{schoolslug}
  3. Clone locally for branding setup
  4. Update package.json, README.md, brand config
  5. Push to main, ready for Vercel link
What we’re doing

Each school gets its own dedicated Supabase project. No shared database. This is FERPA isolation, audit-trail isolation, and incident-blast-radius isolation. One school’s issue can never affect another.

How we do it
  1. Reference: master schema lives in supabase.com/dashboard/project/sdfkqiijyrtnzfnflywk
  2. Create new project: atticus-{schoolslug} in same org
  3. Region: us-east-1 (or closest to school)
  4. Run migrations from atticus-template/supabase/migrations/
  5. Enable Point-in-Time Recovery (PITR) for daily backups
What we’re doing

Vercel hosts the front-end and serverless functions. Each school’s repo deploys to its own Vercel project — auto-deploy on push to main, with preview deploys on PRs for staging.

How we do it
  1. Reference template: vercel.com/thomassonger-5425s-projects/blueprint-school
  2. New project: import atticus-{schoolslug} from GitHub
  3. Framework: Next.js 15, App Router
  4. Build command, output directory: defaults from template
  5. Production branch: main
What we’re doing

Each school gets a branded URL — either a subdomain we own ({schoolslug}.atticus.app) or the school’s own domain (compliance.{school}.edu). Vercel auto-provisions SSL via Let’s Encrypt.

How we do it
  1. Add domain in Vercel project settings
  2. Update DNS: CNAME → cname.vercel-dns.com
  3. Verify SSL cert auto-issues (typically < 5 min after DNS propagates)
  4. Set up www redirect to apex
  5. Enable HSTS for security
What we’re doing

Every external service connection runs through env vars — never hard-coded. We have a master list from the template; each school’s deployment gets its own values.

How we do it
  1. ANTHROPIC_API_KEY — Atticus master, shared
  2. NEXT_PUBLIC_SUPABASE_URL — school-specific
  3. SUPABASE_SERVICE_ROLE_KEY — school-specific, server only
  4. CALENDLY_WEBHOOK_SECRET — per-school webhook
  5. SCHOOL_BRAND_NAME, SCHOOL_PRIMARY_COLOR, SCHOOL_LOGO_URL
  6. SENTRY_DSN — error monitoring
What we’re doing

If something breaks at 2am, we want to know before the school does. Sentry catches every error with stack traces. Vercel Analytics tracks usage so we can see adoption patterns.

How we do it
  1. Create Sentry project: atticus-{schoolslug}
  2. Inject SENTRY_DSN into Vercel env
  3. Enable Vercel Analytics in project dashboard
  4. Configure alert routing: critical → Atticus on-call, warnings → daily digest
  5. Set up uptime monitoring (e.g., Better Stack) on production URL
What we’re doing

Per the partnership: Atticus is the contracting party and merchant of record. We bill the school directly via Stripe; CMG’s revenue share pays out monthly via partnership accounting.

How we do it
  1. Create Stripe customer: {school name}
  2. Set up subscription: monthly billing, $299 base + per-student usage
  3. Configure usage-based billing on student count metric
  4. Set up tax handling (state-specific where applicable)
  5. Schedule monthly invoice + auto-charge
What we’re doing

Before we move to database population and integrations, we verify the foundation works. Site loads, login works, Supabase connection is alive, Sentry is reporting, branding is correct.

How we do it
  1. Visit production URL, verify SSL cert
  2. Test login flow with Atticus admin account
  3. Verify Supabase queries succeed (check dashboard logs)
  4. Throw a test error, confirm Sentry catches it
  5. Confirm branding: colors, logo, school name throughout UI
  6. Mobile responsive check on iOS Safari + Android Chrome
